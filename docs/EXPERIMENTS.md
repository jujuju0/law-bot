### E0 — naive 500자 + dense (2026-10-08)
- **가설:** 기준선. 법률 조문을 이어 붙여 고정 500자로 자르면 조 경계가 깨져 검색 정밀도가 낮을 것.
- **변경:** `ai_basic_law_naive`(법률 50청크), `RetrievalConfig(collection=naive, sources=("law",))`
- **결과 파일:** `eval/results/20261008-134515_E0_naive.json`
- **수치:** Hit@1 0.517 / Hit@3 0.655 / MRR 0.590
- **해석:** naive 청크는 평균 2~3개 조에 걸쳐 있고 평가가 `covers` 중 하나만 맞아도 적중으로 보므로 **E0에 유리한 채점**이다. 그럼에도 조문번호 질문(article_lookup)은 0/4.
- **결정:** 기준선

### E1 — 구조 청킹 + dense, 헤더 없음 (2026-10-08)
- **가설:** API 계층(조/항/호) 그대로 청킹하면 조문 단위 질문의 정밀도가 오른다.
- **변경:** `ai_basic_law_raw`(구조 청크 236개를 헤더 없이 `text`로 임베딩), sources=law
- **결과 파일:** `eval/results/20261008-134515_E1_structure.json`
- **수치:** Hit@1 0.517→0.586 (+0.07) / Hit@3 0.655 (±0) / MRR 0.590→0.629 (+0.04)
- **유형별 변화:** cross_ref 0.67→1.00, annex 0.33→0.67, article_lookup 0→0.25 / colloquial 0.50→0.17, definition 1.00→0.75
- **개선:** q009(법 31조 요약 1위), q026(제32조+제40조 1위), q031 / **악화:** q012, q013, q015(일상어 — 큰 naive 청크가 여러 조 문맥을 함께 담아 유리했음), q002
- **해석:** 정밀도(Hit@1·MRR)는 개선. 일상어 질문은 짧은 구조 청크와 어휘가 안 맞아 악화 → Multi-Query·Term expansion 대상.
- **결정:** 채택 (구조 청킹을 이후 모든 실험의 기반으로 사용)

### E2 — + contextual header (2026-10-08)
- **가설:** `[법률 > 제4장 …] 제31조(제목)` 헤더를 붙여 임베딩하면 조 제목·장 정보가 검색 신호가 된다.
- **변경:** `ai_basic_law`(`embed_text` 임베딩)
- **결과 파일:** `eval/results/20261008-134516_E2_header.json`
- **수치:** Hit@1 0.586→0.552 (−0.03, 1문항) / Hit@3 0.655 (±0) / MRR 0.629→0.586 / Full-R@5 0.048→0.095
- **유형별 변화:** 없음 (유형별 Hit@3 동일)
- **해석:** 1문항 차이로 노이즈 범위. dense만으로는 헤더 효과가 드러나지 않는다. 헤더는 BM25(조 제목 토큰)·Router에서 활용되므로 유지.
- **공통 실패:** 시행령 조문번호 질문(q008·q011)은 sources=law라 구조적으로 불가(→E8), 부칙 청크가 "제N조" 질문 상위를 차지(q007·q044), 조문번호 질문을 dense가 못 찾음(→Router).
- **결정:** 유지 (기각할 근거도 없음, 이후 기법의 기반)

### E3 — + BM25 + RRF (2026-10-08)
- **가설:** 법률 용어 정확 일치(국내대리인, 과태료, 영향평가)를 dense가 놓치는 경우를 BM25가 보완한다.
- **변경:** `use_bm25=True, rrf_k=60`. `rag/bm25.py` — kiwipiepy 내용어(NNG·NNP·VV·VA·XR·SL·SN) 토큰, **BM25 전용 Kiwi에 법령 정의어 51개(`"…"이란`) 사용자 사전 등록**(`인공지능`이 `인공/지능`으로 쪼개져 거의 모든 청크에 매칭되던 문제), 1음절 경동사·`법` 불용어. 색인 대상 `embed_text`.
- **결과 파일:** `eval/results/20261008-135011_E3_hybrid.json`
- **수치(E2 대비):** Hit@1 0.552→0.483 (−2문항) / Hit@3 0.655→0.621 (−1) / Hit@5 0.655→0.690 (+1) / Full-R@5 0.095→0.143 / **Cand-R@20 0.517→0.603 (+0.086)**, 후보 Hit@20 0.759→0.862 (+3문항)
- **참고:** BM25 단독 Hit@1 0.586·MRR 0.622 (dense 0.552·0.586보다 높음). `rrf_k` 민감도 1/5/10/20/60 → Hit@1 0.55/0.48/0.48/0.48/0.48, Hit@3 0.69/0.69/0.66/0.66/0.62 — 차이 1~2문항으로 노이즈 범위라 표준값 60 유지(dev 과적합 회피).
- **개선:** q013(AI 그림 표시 → 법 제31조 2위), q038·q040 / **악화:** q005(정의 → 3위), q009("31조 요약" → 4위, BM25가 `31` 토큰으로 다른 조의 "제31조" 언급을 끌어옴), q014
- **해석:** 상위 순위 정밀도는 RRF로 dense·BM25 의견이 갈릴 때 평준화돼 약간 떨어지지만, **정답 후보를 20개 안으로 끌어오는 재현율은 확실히 오른다.** 순위 정밀도는 다음 단계(Rerank)가 담당하는 구조이므로 1단계 후보 생성기로 채택. 조문번호 질문의 숫자 매칭 노이즈는 Router(E5)로 해결.
- **결정:** 채택 (근거: Cand-R@20 +0.086, Hit@5·Full-R@5 개선. Hit@1 하락은 E4 Rerank 결과로 재확인)
